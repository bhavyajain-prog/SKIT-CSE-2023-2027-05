# Deployment

Production runs on free tiers and deploys from `main`.

| Part | Host | Config | URL |
|---|---|---|---|
| Frontend (Vite static build) | Vercel | `frontend/vercel.json` | `https://kronos.nerfex.dev` |
| Backend (Spring Boot, Docker) | Render, Singapore, free | `render.yaml` | `https://api-kronos.nerfex.dev` |
| Database (PostgreSQL) | Supabase, Mumbai (`ap-south-1`), free | Flyway migrations at startup | Default Supabase host |

The browser only talks to `kronos.nerfex.dev`. Vercel rewrites `/api/*` to
`api-kronos.nerfex.dev`, so the app is same-origin and needs no CORS setup.
The backend domain is a stable rewrite target: moving or renaming the Render
service only changes a DNS record, not the repo.

## DNS records (nerfex.dev)

| Name | Type | Target |
|---|---|---|
| `kronos` | CNAME | `cname.vercel-dns.com` |
| `api-kronos` | CNAME | `kronostt-api.onrender.com` |

Both platforms issue the HTTPS certificates. If the DNS provider is
Cloudflare, set both records to DNS only (grey cloud) so the certificates
can be issued.

## Free-tier limits

- **Render** stops the backend after 15 minutes without traffic. The first
  request after that takes about a minute while it starts again.
- **Supabase** pauses a project after 7 days without activity. Resume it
  from the dashboard. The database is limited to 500 MB.
- **Render** gives the instance 512 MB of RAM, and `JAVA_TOOL_OPTIONS` in
  `render.yaml` keeps the JVM inside it.

## How a change goes live

1. A PR is merged to `main`.
2. **Backend:** Render waits for Backend CI to pass on that commit
   (`autoDeployTrigger: checksPass`), then builds `backend/Dockerfile`. It
   only rebuilds when something under `backend/` changed. Flyway applies new
   migrations at startup.
3. **Frontend:** Vercel builds `frontend/` and publishes it. Every PR also
   gets its own preview URL.

## Environment variables

**Render** (backend). Values marked `sync: false` in `render.yaml` are
entered in the Render dashboard, not committed.

| Key | Value |
|---|---|
| `DB_URL` | `jdbc:postgresql://aws-0-ap-south-1.pooler.supabase.com:5432/postgres?sslmode=require` |
| `DB_USERNAME` | `postgres.twwipoylejynablirpbl` (project `kronostt`, PostgreSQL 17) |
| `DB_PASSWORD` | The Supabase database password |
| `JWT_SECRET` | Generated by Render |
| `BOOTSTRAP_ADMIN_EMAIL` | Email of the first SUPER_ADMIN |
| `BOOTSTRAP_ADMIN_PASSWORD` | Its initial password, at least 12 characters |

## Admins

On every startup the backend checks the `BOOTSTRAP_ADMIN_*` variables:

- If they are unset, or a user with that email already exists (in any
  letter case), it changes nothing.
- Otherwise it creates that user as `SUPER_ADMIN`.

Changing the variables later doesn't reset that admin's password.

More admins are added by existing admins:

- `POST /api/admin/users` creates a user with roles.
- `PUT /api/admin/users/{id}/roles` changes an existing user's roles.

Both need `USER_MANAGE`, and nobody can grant a role higher than their own.
A `SUPER_ADMIN` can create or promote other `SUPER_ADMIN`s, and an
`INSTITUTE_ADMIN` can grant roles up to `INSTITUTE_ADMIN`. Nobody can change
their own roles, so the last `SUPER_ADMIN` can't demote themselves.

Use the Supabase **session pooler** (port 5432 on the `pooler.supabase.com`
host). Not the others:

- The direct connection (`db.<ref>.supabase.co`) is IPv6-only, and Render
  can't reach it.
- The transaction pooler (port 6543) breaks prepared statements and Flyway.

**Vercel** (frontend):

| Key | Value |
|---|---|
| `VITE_API_BASE_URL` | `/api` |

## One-time setup

1. **Supabase:** create the project in Mumbai. Copy the session pooler
   connection string from Connect, then Session pooler.
2. **Render:** in the dashboard, choose New, then Blueprint, and pick this
   repository. Fill in `DB_URL`, `DB_USERNAME` and `DB_PASSWORD`.
3. **Vercel:** import the repository with Root Directory set to `frontend`,
   add `VITE_API_BASE_URL=/api`, and set the production branch to `main`.
4. **Domains:** add the two CNAME records above. Add `kronos.nerfex.dev` to
   the Vercel project. The Render domain comes from `render.yaml`.
5. **Check:** `https://api-kronos.nerfex.dev/api/health` returns `200`,
   then `https://kronos.nerfex.dev/api/health` returns `200` too.

Bring up the backend domain before the frontend goes live, because the
frontend's `/api` rewrite points at it. If Render gives the service a
hostname other than `kronostt-api.onrender.com`, change the `api-kronos`
CNAME to match.

## Local full stack

Running `docker compose up --build` starts the same images locally, with a
local Postgres instead of Supabase. See `.env.example`.
